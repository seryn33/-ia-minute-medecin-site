Projets et Skills : Claude à votre main

Le Projet retient votre contexte, la Skill retient votre geste. Dix minutes de réglage, et vous ne réexpliquez plus jamais deux fois la même chose.

Mise à jour : 5 août 2026. Les interfaces évoluent vite : les chemins d'écran peuvent bouger, les principes restent.

Trois choses à comprendre avant de cliquer

  • Un Projet, c'est un classeur. Des instructions permanentes, des documents de référence, et toutes les conversations d'un même thème au même endroit. Ce que vous y déposez une fois (votre spécialité, vos gabarits, vos règles) vaut pour toutes les conversations du classeur. Disponible sur toutes les offres, y compris gratuite.
  • Une Skill, c'est un savoir-faire. Une procédure que Claude charge de lui-même quand la tâche s'y prête : « comment je rédige un courrier de spécialiste », « comment je structure un compte rendu ». Lancées fin 2025, elles sont réservées aux offres payantes.
  • L'ordre d'installation compte. Un Projet d'abord : dix minutes, gain immédiat. Des Skills ensuite, quand un geste devient répétitif. Et la même règle que partout dans ce livre : aucune donnée de patient, ni dans les instructions, ni dans les documents.

La parenté avec les Custom GPT (page dédiée du livre) et les Gems de Gemini est directe : même idée (capitaliser vos consignes) avec une différence d'architecture. Le Projet garde en plus vos documents et vos conversations ensemble ; la Skill, elle, voyage : une fois créée, elle s'applique partout où la tâche la réclame.

Votre premier Projet, en trois temps

Sur claude.ai, connecté à votre compte. Comptez dix minutes, une fois pour toutes.

1

Créez et nommez par usage

Menu « Projets », puis « Nouveau projet ». Un nom d'usage, pas de poésie : « Courriers du cabinet », « Protocoles », « Préparation DPC ». Un projet = un thème ; trois projets bien découpés valent mieux qu'un fourre-tout.

2

Écrivez les instructions permanentes

C'est le cœur du réglage : qui vous êtes, pour qui vous écrivez, vos règles non négociables. Le bloc ci-dessous est un point de départ éprouvé : adaptez la spécialité et le style, puis collez-le dans le champ « Instructions » du projet.

3

Déposez les documents de référence

Deux ou trois gabarits de courriers anonymisés, vos protocoles maison, les recommandations que vous citez sans cesse. Chaque conversation du projet s'appuiera dessus sans que vous les re-téléversiez. Relisez chaque document avant dépôt : ce qui entre dans le classeur y reste.

Instructions permanentes type : projet « Courriers du cabinet »

Tu assistes un médecin [spécialité] exerçant en France, pour la rédaction de ses courriers professionnels.

Règles permanentes :
1. Vouvoiement, ton confraternel sobre, sans emphase.
2. Médicaments en DCI. Aucune abréviation non standard.
3. Structure par défaut : motif d'adressage, éléments cliniques, question posée, formule de courtoisie courte.
4. Longueur : une page maximum, phrases courtes.
5. Je te donne toujours des situations anonymisées ; si un élément ressemble à une donnée identifiante, signale-le avant de rédiger.
6. Si une information clinique te manque pour conclure, pose la question au lieu d'inventer.
7. Appuie-toi sur les gabarits fournis dans ce projet : même plan, mêmes tournures.

Votre première Skill, en trois temps

Offres payantes. Une Skill se rédige comme une procédure qualité : quand l'utiliser, comment faire, à quoi ressemble le résultat.

1

Activez les Skills dans les réglages

Paramètres du compte, rubrique fonctionnalités : activez les Skills, puis « Créer une skill ». Claude propose de vous accompagner dans la rédaction : acceptez, c'est le plus court chemin.

2

Décrivez le savoir-faire, pas le souhait

Trois ingrédients : le déclencheur (« quand on me demande un compte rendu de consultation »), la procédure pas à pas, le gabarit du résultat. Le bloc ci-dessous montre la structure : c'est votre façon de faire, mise en fiche une fois pour toutes.

3

Testez sur trois cas réels, puis corrigez

Trois situations anonymisées de votre semaine passée. Comparez au résultat que vous auriez produit ; corrigez la Skill, pas le résultat. Deux itérations suffisent en général pour que le geste soit fidèle.

Trame d'une Skill « Compte rendu structuré »

QUAND L'UTILISER
Quand on me demande de transformer des notes de consultation en compte rendu.

PROCÉDURE
1. Classer les éléments fournis : motif, antécédents pertinents, examen, synthèse, conduite à tenir.
2. Ne rien inventer : un élément absent des notes reste absent du compte rendu.
3. Rédiger au style télégraphique médical, DCI uniquement.
4. Terminer par la liste « À vérifier par le médecin » : tout élément incertain ou manquant.

FORMAT DU RÉSULTAT
[Motif] / [Antécédents pertinents] / [Examen] / [Synthèse] / [Conduite à tenir] / [À vérifier]

Le cadre, en trois lignes

  • Aucune donnée de patient dans les instructions, les documents ou les conversations d'un projet : un classeur, ça se garde, raison de plus pour n'y ranger que de l'anonyme.
  • Vérifiez le réglage de confidentialité : depuis fin septembre 2025, vous choisissez explicitement si vos conversations peuvent servir à améliorer les modèles. Paramètres, rubrique confidentialité : cochez en conscience.
  • Une Skill ne dispense de rien : relecture et signature restent des actes médicaux. La Skill industrialise le brouillon, jamais la validation.

Le Projet retient le contexte, la Skill retient le geste. Vous, vous gardez la décision. Dix minutes de réglage pour des mois de prompts raccourcis : le meilleur rendement du livre.

Questions fréquentes

Projet Claude, Custom GPT, Gem : lequel choisir ?

Celui de l'écosystème où vous êtes déjà. Les trois capitalisent vos consignes ; les Projets y ajoutent le classement des conversations, les Custom GPT le partage public le plus rodé, les Gems l'intégration Google Workspace. Le livre consacre une page à chacun ; la méthode ORCF, elle, est portable partout.

Mes documents servent-ils à entraîner les modèles ?

C'est votre réglage qui décide : l'éditeur demande depuis septembre 2025 un choix explicite, modifiable dans les paramètres de confidentialité. Sur les offres professionnelles (Team, Enterprise), les données ne servent pas à l'entraînement par défaut. Dans tous les cas, la règle du livre prime : rien d'identifiant n'entre, donc rien d'identifiant ne peut fuir.

Puis-je partager un Projet avec mon associé ou ma secrétaire ?

Le partage de projets existe sur les offres d'équipe (Team et Enterprise) : mêmes instructions, mêmes documents, chacun ses conversations. Pour un cabinet de groupe, c'est le moyen d'harmoniser courriers et protocoles en une seule installation. Sur les offres individuelles, chacun reconstruit son projet : dix minutes, en copiant les mêmes instructions.

Par où commencer si je n'ai que quinze minutes ?

Créez le projet « Courriers du cabinet », collez les instructions type ci-dessus, déposez deux courriers anonymisés dont vous êtes satisfait, et demandez votre premier adressage. Le gain est perceptible à la première utilisation ; les Skills attendront le mois prochain.
